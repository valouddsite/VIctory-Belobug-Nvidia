# NVIDIA RTX 5060 compatibility plan

## Target and current evidence

Target GPU: NVIDIA GeForce RTX 5060, 8 GB dedicated VRAM, on Windows 11 with the Direct3D 12 runtime.

The inherited code already creates a host D3D12 device through a generic DXGI adapter-selection routine. It prefers a high-performance adapter that can create a D3D12 device and supports Shader Model 6.6; `VICTORY_D3D12_ADAPTER` can select an adapter by DXGI index or name. The runtime logs the selected adapter and its dedicated VRAM. The host checks Shader Model 6.6 and mesh-shader support, and records the host wave-lane range. AMD-specific RDNA translation is gated by the adapter vendor ID; the wider indirect-dispatch path is also restricted to AMD. NVIDIA is therefore not currently being mislabeled as AMD for those paths.

The inherited DXGI emulation layer reports a virtual console adapter to the title. That reported adapter is intentionally distinct from the host GPU and must not be changed to NVIDIA merely to identify the physical RTX 5060.

The repository's historical measurements are not RTX 5060 measurements:
- RX 7900 XTX: approximately 45 ms/frame in one Series S scene, with 10.5 GB reported VRAM use.
- RTX 3090: a contributor reported that the prison scene rendered, but two warm Series S runs averaged approximately 545 and 532 ms/frame and used around 10 GB VRAM.

These results show that NVIDIA execution has been observed on an RTX 3090, but they do not establish compatibility or performance on an RTX 5060. The RTX 5060 has less VRAM than that reported workload, so memory pressure is a primary risk.

## Work plan

1. **Hardware detection and diagnostics**
   - Verify the selected DXGI adapter is the requested NVIDIA GPU when multiple adapters exist.
   - Log vendor ID, device ID, driver version, shader model, mesh-shader tier, wave-lane range, and dedicated VRAM.
   - Keep explicit adapter selection available; do not silently force NVIDIA on systems without it.

2. **D3D12 capability correctness**
   - Audit assumptions that are specific to AMD/RDNA rather than relying on vendor labels.
   - Keep AMD-specific wave and shader paths gated by actual device capabilities.
   - Add focused unit tests for adapter selection and capability decisions where they can be tested without a physical GPU.

3. **8 GB VRAM behavior**
   - Measure the actual DXGI video-memory budget and usage.
   - Review texture retention, residency, and cache policies under memory pressure.
   - Prefer safe resource eviction and clear diagnostics over guessed fixed VRAM limits.

4. **Validation**
   - Run formatting, Clippy, and workspace tests on Windows x64 MSVC.
   - Record CI results only after GitHub Actions has completed.
   - Runtime validation requires a real RTX 5060; CI compilation alone cannot prove rendering or acceptable frame times.
